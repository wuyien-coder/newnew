# 部署说明

本地轻量运行见 README；生产组件参考 docker-compose.yml 和 .env.production.example。修改配置时不要提交 .env 或实际凭据。

恢复本地全部功能使用 .env.full.example 与 docker-compose.full.yml，完整命令见 README 的“与本地一致的完整版”。该组合启用真实 BGE、真实模型、pgvector、Redis 和 Celery；api 与 worker 共用相同模型缓存、索引卷、上传卷和全量语料。镜像包含完整原文，不依赖创建者电脑的论文目录。

部署前执行 python scripts/verify_corpus.py 与 python scripts/download_models.py。全量启动会校验语料、执行迁移，并在新数据库中导入全部语料及图谱、构建向量。后续启动保留用户对知识库的删除操作。mathknow-full 使用独立的 Compose 项目卷，本地默认 SQLite 也使用 .index/full/mathkb.db，避免混用旧演示数据。若迁移已有实例，先使用正常数据库备份，再在正确配置下运行 scripts/build_index.py --sync-corpus；此操作保留会话和上传资料，可能保留旧样例的重复文本，干净部署的初始文本块数为 9,921。

启动后可运行 scripts/verify_full.py --base-url http://127.0.0.1:8080 验收真实模型流式输出、ReAct 工具调用、全量检索、会话保存、Celery 上传摄取与删除。运行前在环境变量 MATHKB_SERVER__API_TOKEN 填入实例访问令牌。该脚本会调用模型服务并产生少量费用，在 reports/full_acceptance.json 写入验收结果并清理临时会话与文档。

真实模型需要兼容 API 地址、模型名和密钥；BGE 需要 ML 依赖和模型缓存。PostgreSQL 首次迁移需具备创建 vector 扩展的权限。部署前执行 alembic upgrade head。

check_stack.py --require-all 实际检查 PostgreSQL/pgvector、Redis 和 Celery worker，不会把未配置或连接失败写成通过。Celery 生产环境使用 Linux，默认并发 1，不能据此推导吞吐能力。

共享 Bearer token 仅用于应用访问控制，不提供用户账户、多租户隔离或角色权限。容器配置未验证生产容量、高可用或灾难恢复。
